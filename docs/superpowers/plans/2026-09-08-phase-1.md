# Phase 1: Landing and Idea Input

Sources: root product PRD, DESIGN.md, output template, and approved implementation decisions. Root documents remain unchanged.

1. Scaffold Next.js 16 App Router, strict TypeScript, Tailwind v4, Lucide, local Cormorant 300 and Inter 300/400 fonts. No database, AI provider, payments, or git operations.
2. Build a server-rendered editorial landing with ten meaningful sections: hero wizard, starter ideas, process, two-file output sample, clarification, stack, skills versus MCP, visual direction, privacy/self-hosting, and FAQ/final action. Use exact cream/ink/ash/blue tokens, outlined pills, sharp panels, generous responsive spacing, and no fabricated proof.
3. Isolate the client wizard and its validation. Count trimmed Unicode code points (20-5000), offer six optional PRD stack categories with no-preference defaults, support starter examples, and retain the idea/stack when entering or returning from an explicitly unfinished Phase 2 handoff. State is memory-only; refresh clears it.
4. Add original SVG document/interface illustrations and a bounded GSAP image pool confined to the hero's noninteractive header. Mouse/fine-pointer only, disabled for reduced motion; clean listeners and tweens on unmount.
5. Test validation boundaries and wizard retention, run tests/typecheck/lint/production build, fix failures, and start development on port 3000 for parent browser QA. Report evidence and remaining Phase 2+ gaps; do not check off root PRD tasks.

Design precedence: DESIGN.md palette and typography substitutes win over the output template's user-project presets. Approved readable black body text, sentence-case labels, restrained blue interaction accents, and layout variety resolve conflicting reference examples. This is a usable Phase 1 prototype, not a claim that generation is live.
